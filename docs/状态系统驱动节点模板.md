# 《黄昏居酒屋》状态系统驱动节点模板

> 更新时间：2026-07-16
> 本文只给出当前代码支持的新内容写法。请先复制最接近的模板，再替换角色、节点、配方和材料 ID。
> 设计原则与字段语义见 `docs/状态系统驱动内容规范.md`。

## 1. 使用流程

1. 在角色目录中选择正确文件：主线、教学、聊天、隐藏、观察或图鉴。
2. 为节点、选项和效果分配稳定 ID。
3. 用显式 `exit` 连接所有节点。
4. 确认调酒成功、失败两条结果都存在。
5. 运行：

```bash
npm run content:check
npm run narrative:check
npm run narrative:simulate
npm test
```

仓库现有的 `UNREACHABLE_MAIN_NODE` warning 需保留清单并逐项消化。warning 不等于构建 error，也不代表这些节点已经处理完；数量以 `npm run narrative:check` 的实时输出为准，提交前应确认本次改动没有无解释地增加 warning。

## 2. 一条完整主线模板

这个例子依次经过：不同选项回应 → 普通跳转 → 观察 → 调酒请求 → 成功/失败结果 → 奖励、日记、图鉴和好感度 → 结束来访。

```yaml
character_id: guest_id
nodes:
  - event_id: guest_001_intro
    trigger_condition:
      need_event: []
      need_time: any
      need_item: []
    script_flow:
      - type: env
        content:
          - 门外的人收起伞，却没有立刻进来。
      - type: npc
        content:
          - 「这里……还营业吗？」
      - type: inner
        content:
          - 他问的是营业时间，目光却一直停在最里面的空座。
    player_options:
      - id: invite_him_inside
        text: 「先进来坐吧，外面很冷。」
        branch_type: flavor
        script_flow:
          - type: npc
            content:
              - 「谢谢。我只待一会儿。」
          - type: env
            content:
              - 他的肩膀终于松下来一点。
        effects:
          - id: kindness_builds_affection
            type: relationship.change
            target: self
            axis: affection
            amount: 2
            feedback: 你的体贴降低了他的戒备。
        effect_scope: game
        impact_log: 请他进屋避寒

      - id: ask_why_he_came
        text: 「你在找什么人吗？」
        branch_type: flavor
        script_flow:
          - type: npc
            content:
              - 「……没有。我大概走错了。」
          - type: env
            content:
              - 他把一张折皱的车票塞回口袋。
        effects:
          - id: direct_question_reduces_affection
            type: relationship.change
            target: self
            axis: affection
            amount: -1
            feedback: 过于直接的追问让他重新警觉起来。
        effect_scope: game
        impact_log: 直接追问他的来意
    exit:
      kind: next
      target: guest_002_observation_cue

  - event_id: guest_002_observation_cue
    trigger_condition:
      need_event:
        - guest_001_intro
      need_time: any
      need_item: []
    script_flow:
      - type: env
        content:
          - 他坐下时，口袋里的车票露出了一角。
      - type: inner
        content:
          - 票面似乎有被水泡过的痕迹。
    player_options: []
    exit:
      kind: observation
      prompt: 观察他口袋里露出的旧车票
      continue_node: guest_003_drink_request
      feature_groups:
        - carried_item

  - event_id: guest_003_drink_request
    trigger_condition:
      need_event:
        - guest_002_observation_cue
      need_time: any
      need_item: []
    script_flow:
      - type: npc
        content:
          - 「能调一杯让人记起归途的酒吗？」
      - type: env
        content:
          - 他说完，又看了一眼那张已经褪色的车票。
    player_options: []
    exit:
      kind: mixing
      request:
        mode: normal
        request_text: 为他调一杯能让人记起归途的酒
        hint: 那张褪色车票像是他唯一确认方向的东西。
        preferred_drink:
          id: R001
          name: 未竟的生诞
          formula:
            - bc01
            - m04
            - f03
      outcomes:
        success: guest_003_mixing_success
        fail: guest_003_mixing_fail

  - event_id: guest_003_mixing_success
    trigger_condition:
      need_event:
        - guest_003_drink_request
      need_time: any
      need_item: []
    script_flow:
      - type: env
        content:
          - 他抿了一口，终于把车票完整地放到吧台上。
      - type: npc
        content:
          - 「原来不是路不见了，是我一直不敢回头。」
    player_options: []
    reward:
      details:
        type: recipe
        id: R001
        name: 未竟的生诞
        description: 一杯承载未竟心愿的酒。
        quantity: 1
    story_unlocks:
      chapters:
        - id: guest_chapter_01
          reason: 他终于承认自己害怕回头。
    diary_note: "那张旧车票并没有指向错误的地方；真正让他迷路的是不敢回头。"
    on_complete:
      effect_scope: game
      effects:
        - id: understood_his_request
          type: relationship.change
          target: self
          axis: affection
          amount: 4
          feedback: 这杯酒让他觉得自己被理解了。
    exit:
      kind: end_visit

  - event_id: guest_003_mixing_fail
    trigger_condition:
      need_event:
        - guest_003_drink_request
      need_time: any
      need_item: []
    script_flow:
      - type: npc
        content:
          - 「不是这个味道……不过，谢谢你。」
      - type: env
        content:
          - 他把车票收了回去，没有再提归途。
    player_options: []
    diary_note: "这杯酒没能让他面对那张车票背后的记忆。"
    on_complete:
      effect_scope: game
      effects:
        - id: mismatched_drink_reduces_affection
          type: relationship.change
          target: self
          axis: affection
          amount: -1
          feedback: 这杯酒没有真正回应他的请求。
    exit:
      kind: end_visit
```

要点：

- `guest_003_drink_request` 的正文先播放，正文结束才进入调酒。
- 普通调酒的 `success` 与 `fail` 都填写真实目标；只有明确设计为原地教学重试时，才允许 `fail: null`。
- `diary_note` 是单个字符串。
- 选项点击时结算选项效果；结果节点完成时结算 `on_complete`。

## 3. 带专属剧情目标的选项

选项自己的 `next_node` 可以覆盖节点共同出口。`fallback_node` 是尚未实现条件求值器的历史预留字段，新内容不得填写非空值。节点本身仍然使用 `exit`：

```yaml
- event_id: guest_branch_question
  trigger_condition:
    need_event:
      - guest_previous_event
    need_time: any
    need_item: []
  script_flow:
    - type: npc
      content:
        - 「你觉得我应该回去吗？」
  player_options:
    - id: advise_returning
      text: 「至少该让等你的人知道真相。」
      branch_type: plot
      script_flow:
        - type: npc
          content:
            - 「……你说得对。」
      next_node: guest_return_route
      impact_log: 劝他回去面对真相

    - id: respect_his_choice
      text: 「决定权在你，我会听你说完。」
      branch_type: flavor
      script_flow:
        - type: npc
          content:
            - 「谢谢。很久没人愿意只听我说了。」
      impact_log: 尊重他的选择
  exit:
    kind: next
    target: guest_shared_route
```

不要把节点级旧 `next_node` 与选项 `next_node` 混淆；不要用 `fallback_node` 假装已有运行时条件分支。

### 3.1 逐项查看的选择组

需要玩家依次查看多个方向时，节点内所有选项统一写为 `branch_type: choice`。这类选项不声明自己的 `next_node` / `fallback_node`；完成当前可用项后，解释器统一执行节点出口：

```yaml
- event_id: guest_inspect_belongings
  trigger_condition:
    need_event:
      - guest_previous_event
    need_time: any
    need_item: []
  script_flow:
    - type: inner
      content:
        - 他的随身物品似乎各自藏着一段来历。
  player_options:
    - id: inspect_ticket
      text: 查看旧车票
      branch_type: choice
      script_flow:
        - type: env
          content:
            - 票面终点被反复折叠，已经看不清了。

    - id: inspect_key
      text: 查看生锈的钥匙
      branch_type: choice
      condition:
        need_item: old_key
        locked_text: 还没有拿到那把旧钥匙
      script_flow:
        - type: npc
          content:
            - 「那扇门早就不在了，我却一直留着它。」
  exit:
    kind: next
    target: guest_after_inspection
```

被 `need_item` 锁定的选项不计入本次必须完成项，因此没有对应物品时也不会卡死；有物品时，模拟器会覆盖新增可用分支。

## 4. 需要物品的选项

当前选项条件只支持 `need_item` 与 `locked_text`：

```yaml
player_options:
  - id: return_the_ticket
    text: 「把这张车票还给他。」
    branch_type: plot
    condition:
      need_item: old_ticket
      locked_text: 需要先找到那张旧车票
    script_flow:
      - type: npc
        content:
          - 「你在哪里找到它的？」
    next_node: guest_ticket_recovered
```

不要在选项 `condition` 中自创 `need_event`、`need_flag` 等字段。

## 5. 观察数据模板

剧情节点用 `exit.kind: observation` 进入观察；可发现的内容写在 `observations.yaml`：

```yaml
character_id: guest_id
observations:
  - id: obs_old_ticket
    area: coat_pocket
    group: carried_item
    objective: 一张被雨水泡皱的旧车票，日期已经模糊。
    subjective: 他一直确认它还在，仿佛那是唯一的路标。
    hint: 注意他反复按住的外套口袋。
    revealed_at: guest_002_observation_cue
    x: 62
    y: 48
```

配套节点出口：

```yaml
exit:
  kind: observation
  prompt: 观察他反复按住的外套口袋
  continue_node: guest_after_observation
  feature_groups:
    - carried_item
```

不要再写 `trigger_observation`。

## 6. 教学链模板

教学说明节点带 `teaching`，其出口必须是 `next`；下一个独立节点播放调酒前正文，再用 `mixing` 出口进入实际调酒。

```yaml
character_id: mentor_id
nodes:
  - event_id: mentor_teaching_01
    trigger_condition:
      need_event: []
      need_time: W1_D1_Dusk
      need_item: []
    script_flow:
      - type: npc
        content:
          - 「先尝清酒本身，再决定苏打水该放多少。」
    player_options: []
    teaching:
      recipe:
        id: R021
        name: 纯米嗨棒
        ingredients:
          - 纯米清酒 (bj01)
          - 苏打水 (m01)
        formula:
          - bj01
          - m01
        steps:
          - 以纯米清酒作为基酒。
          - 加入苏打水。
          - 轻轻搅拌，不要破坏气泡。
      mixing_steps_display:
        - 选择纯米清酒
        - 加入苏打水
        - 轻轻搅拌
      tip: 「简单的酒，最能暴露比例是否准确。」
    exit:
      kind: next
      target: mentor_teaching_01_mixing

  - event_id: mentor_teaching_01_mixing
    trigger_condition:
      need_event:
        - mentor_teaching_01
      need_time: any
      need_item: []
    script_flow:
      - type: env
        content:
          - 他把量杯推到你面前，示意你亲手完成。
    player_options: []
    exit:
      kind: mixing
      request:
        mode: teaching
        request_text: 按刚才的步骤调制纯米嗨棒
        hint: 先确认基酒，再控制苏打水比例。
        retry_on_fail: true
        preferred_drink:
          id: R021
          name: 纯米嗨棒
          formula:
            - bj01
            - m01
      outcomes:
        success: mentor_teaching_01_success
        fail: null

  - event_id: mentor_teaching_01_success
    trigger_condition:
      need_event:
        - mentor_teaching_01_mixing
      need_time: any
      need_item: []
    script_flow:
      - type: npc
        content:
          - 「不错。你没有让任何一种味道抢戏。」
    player_options: []
    complete_teaching: true
    reward:
      details:
        type: recipe
        id: R021
        name: 纯米嗨棒
        description: 以纯米清酒与苏打水调制的基础嗨棒。
        quantity: 1
    exit:
      kind: end_visit

```

不要把 `teaching` 对象放在调酒节点上；带 `teaching` 的教学说明节点必须先以 `next` 指向调酒节点。

这里的 `fail: null + retry_on_fail: true` 表示失败后留在调酒并重试。若改为非空 `fail` 结果节点，显式失败目标优先，运行时不会再原地重试。

## 7. 节点完成效果模板

没有玩家选项也可以在节点完成时改变好感度：

```yaml
- event_id: guest_kept_promise
  trigger_condition:
    need_event:
      - guest_previous_event
    need_time: any
    need_item: []
  script_flow:
    - type: npc
      content:
        - 「你真的替我保管到今天了。」
  player_options: []
  on_complete:
    effect_scope: game
    effects:
      - id: promise_kept_builds_affection
        type: relationship.change
        target: self
        axis: affection
        amount: 5
        feedback: 信守承诺显著加深了他对你的信任。
  exit:
    kind: end_visit
```

`effect_scope` 可改为 `visit`，表示每次来访最多结算一次；省略时默认为 `game`。

## 9. 聊天与隐藏节点模板

`nodes_chat.yaml` 与 `nodes_hidden.yaml` 使用轻量正文，但出口仍然显式：

```yaml
character_id: guest_id
nodes:
  - id: chat_idle_001
    event_id: guest_idle_001
    trigger_condition:
      need_event: []
      need_time: between_visits
      need_item: []
    atmosphere_lines:
      - 他看着窗外渐停的雨，手指轻轻敲着杯沿。
    speaker: null
    content:
      - 「雨停以后，路会不会就出现了？」
    player_options: []
    exit:
      kind: end_visit
```

若聊天或隐藏节点需要串联：

```yaml
exit:
  kind: next
  target: guest_hidden_followup
```

## 10. 图鉴模板

`gallery.yaml`：

```yaml
character_id: guest_id
base_info:
  name: 角色名
  age: 27
  occupation: 旅人
  description: |
    玩家初见时能够确认的外观和身份。
  type: 迷失者

profile_sections:
  - id: surface
    title: 初见
    content: |
      只写浅层可见信息，不提前泄露完整真相。
    unlock_condition: guest_001_intro
    depth_level: 1

  - id: old_ticket
    title: 褪色的车票
    content: |
      观察后确认的事实，以及它对角色意味着什么。
    unlock_condition: obs_old_ticket
    depth_level: 2

  - id: guest_chapter_01
    title: 最后的归途
    content: |
      关键剧情完成后才解锁的完整故事。
    unlock_condition: guest_chapter_01
    depth_level: 3
```

节点章节解锁：

```yaml
story_unlocks:
  chapters:
    - id: guest_chapter_01
      reason: 他终于说出了车票的终点。
```

图鉴的 `unlock_condition` 和节点的章节 `id` 必须与真实事件或章节标识一致。

## 11. 日程模板

`src/assets/schedule.yaml`：

```yaml
schedule:
  - day: W1_D3
    guests:
      - character_id: mentor_id
        start_node: mentor_teaching_01
      - character_id: guest_id
        start_node: guest_001_intro
```

- `day` 使用 `W数字_D数字`。
- `character_id` 必须存在。
- `start_node` 必须是该角色真实节点。
- 日程只负责入口，不负责节点内部跳转。

## 12. 禁止复制的旧写法

下面只用于识别待迁移内容，不可用于新节点：

```yaml
# 节点级旧跳转
next_node: guest_next

# 旧观察触发
trigger_observation:
  prompt: ...
  continue_node: ...

# 旧调酒组合
drink_request: ...
on_mixing_complete: guest_success
on_mixing_fail: guest_fail

# 完全不支持
mixing: ...
```

唯一兼容边界会把前三类旧资源解析成显式出口；裸 `mixing` 会报错。不要在新节点里混写旧字段和 `exit`。

## 13. 提交前检查表

- [ ] 每个新节点都使用 `next`、`observation`、`mixing`、`end_visit` 中的一种显式出口。
- [ ] 没有节点级旧 `next_node`、`trigger_observation`、`drink_request` 或 `on_mixing_*`。
- [ ] 没有裸 `mixing:`。
- [ ] 调酒节点有正文，且理解为先播放正文再进入调酒。
- [ ] 普通调酒同时填写有效的 `success` 与 `fail`；retry-only 教学使用 `fail: null + retry_on_fail: true`。
- [ ] 每个正式选项有稳定 `id`，不同选项有不同回应。
- [ ] `branch_type: choice` 不与其他分支类型混写，也不带 `next_node` / `fallback_node`。
- [ ] 没有填写非空 `fallback_node`。
- [ ] 带 `effects` 的选项一定有 `id`。
- [ ] 好感度效果使用 `relationship.change`、`affection` 和非零 `amount`。
- [ ] 节点完成效果放在 `on_complete`。
- [ ] `effect_scope` 只写 `game` 或 `visit`。
- [ ] `diary_note` 是字符串。
- [ ] 奖励写在 `reward.details`。
- [ ] 观察、教学、奖励、日记、图鉴和日程引用均真实存在。
- [ ] `npm run content:check` 无 error。
- [ ] `npm run narrative:check` 无 error，并审阅 warning 数量和内容。
- [ ] `npm run narrative:simulate` 的所有目标都能结束，没有 unexpected loop、step limit 或 issue。
- [ ] `npm test` 全部通过。
