## SEC-001 / SEC-002 修复契约

生产 Key 数据流固定为：

```text
玩家可选输入 MiniMax Key -> 当前前端页面内存 -> Authorization: Bearer <player-key>
                                           \
无玩家 Key -> Vercel MINIMAX_API_KEY --------> 同源 /api/npc-dialogue 入口解析
  -> request-scoped handler/provider 参数
  -> https://api.minimaxi.com
```

约束：

- 仅支持 MiniMax；客户端不能选择 provider、model 或 base URL。
- 应用代码不把 Key 写入 JSON body、存档、业务日志、响应、服务端模块状态或磁盘；托管层必须配置 Authorization 脱敏。
- 刷新、关闭或重启后 Key 消失，玩家需要重填。
- 旧桌面 `config.json` 中的 `MINIMAX_API_KEY` 会在启动时被清除。
- `devtools/` 的 live 调试命令仍允许开发者从环境变量显式提供测试 Key；该目录不进入生产前端或 Electron 包，也不是生产回退路径。
- 如果旧桌面包曾内置并分发作者 Key，必须在 MiniMax 后台另行撤销/轮换；源码修复不能回收旧包。

## 本轮验证目标

- 生产代码和打包输入不再包含 `desktop:pack:author`、作者 Key 文件、作者 Key 环境变量或 `process.env.MINIMAX_API_KEY` 回退；安全守卫与迁移测试只保留这些名称作为拒绝规则。
- 缺少 Authorization 的 NPC 请求返回 `401`，且不会调用 MiniMax。
- 并发 Key A/Key B 分别进入对应上游请求，不串 Key。
- API Key 不出现在请求 JSON、响应或状态对象中。
- 旧 Electron 明文配置迁移测试通过。
- `npm run content:check`、`npm run lint`、`npm test`、`npm run build` 全部通过。

## 剧情框架里程碑边界

本轮“框架完成”指：内容能够用稳定 ID、显式出口和声明式效果表达；运行时、自动模拟与 Inspector 对同一内容得到同一执行结果；错误内容能在构建前失败；事件/选项事实和好感度能够随存档持久化且幂等结算。

它不代表现有角色文本、段落节奏和所有旧章节已经完成叙事验收。剧情语义和演出衔接统一登记在 `CONTENT-005`，可以在不修改解释器与状态机的前提下逐角色迭代。
